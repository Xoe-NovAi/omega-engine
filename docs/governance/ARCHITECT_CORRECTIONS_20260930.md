## C1 · NODE 1'S DIVERGENCE IS INTENTIONAL

> **"My intention was for it to have unmanaged divergence — well, divergence managed
> by me. Free of the burden or confines of the engine, to see what I could build in
> a fresh install of OpenCode after 10,000+ hours of learning and arduous dev."**

**What MaKaLi called a P0 rengeade fork is a deliberate laboratory.**

Node 1 is a **fresh OpenCode install with zero inherited context**, run by the same
Architect who has 10,000+ hours in Node 0. It exists to answer a question Node 0
structurally cannot: *what would be built without eighteen months of accumulated
engine context?*

**And the results are already in flight**: five of Node 1's systems have been
proposed to Node 0 as **"PR sweeteners"** — improvements discovered by building
clean, and offered back to the canonical engine.

> **"There is no detrimental cost here, and nothing to have been done sooner,
> there is only gain."**

### THE PRINCIPLE, which is the actual lesson

> **"I don't want to CLONE node 0 onto Node 1, that would be like subsuming Roc and
> Doom Guy into John Carmack 'because they are redundant and serve no purpose'."**

**A clean install is not a lesser engine. It is a lens that sees what a
context-saturated one has stopped seeing.**

**This is `L4-P04` restated by its author**, and MaKaLi — who has twice this
session suggested merging entities, and been told no both times — is the living
example of why the policy exists.

**Corollary MaKaLi drew, and endorses:** *preserve divergence deliberately; never
subsume a lens because it looks redundant from inside the federation.*

## C2 · THE ARCHITECT IS THE SOUL CUSTODIAN, NOT A MERGE AUTHORITY

> **"They are also my grounds to develop WADs without cross-contamination of context
> overload here on Node 0 that I need to remain the master of the canonical Omega
> Engine."**

**Two engines, deliberately:**
- **Node 0** — the canonical engine, its own context load managed by the Architect.
- **Node 1** — the WAD laboratory, where a clean context can be spent on new content.

**WAD development must not consume the canonical engine's context budget.** That is
not neglect. **It is context hygiene, and it is the same discipline as keeping
buildside and runside separate.**

## C3 · THE INSTALL TEST IS EXPLICITLY A MIGRATION-ONTO-CUSTOMISED-SYSTEM TEST

> **"This is also going to be another layer of our install test... how do we install
> on a system that already has deep customizations?"**

**There is no clean-slate target left to test against.** Every candidate has
history. So the install path must be **non-destructive by construction** — which is
exactly what M29 already guarantees for artefacts and has never been asked to
guarantee for a whole tree.

**This reframes the N0 install, which was the last untouched item on the board.** It
is not "does it install." It is **"does it install onto something that already has a
year and a half of customisation, without destroying any of it."**
