## 1. The Naming Problem: "Artifact B" Is Doing Too Much Work
The Dual-Artifact Rule conflates two distinct problems:
*   **Problem A**: Execution agents copy instructional prose into code.
*   **Problem B**: Execution agents cannot resolve conflicts between competing plans.

**Recommendation**: Split Artifact B into two layers:
*   **B0 (Conflict Resolution Record)**: Documents which plan won each conflict and why. Read by Kali/Verity only.
*   **B1 (Machine Contract)**: Pure executable operations. No prose. No context. Zero pedagogy.
This provides forensic precision to distinguish between bad conflict resolution and contaminated operations.

## 2. The Synaptic Sync Has a Critical Race Condition
A weekly cron job that merges `proposed_lessons.yaml` destroys context. A principle valid for legacy mining may be catastrophic for production soul writes.

**Recommendation**: Implement a **Federated Gnosis Model**:
*   Level 1: Entity-local principles.
*   Level 2: Domain principles (e.g., shared across N1-N5).
*   Level 3: Fleet universal principles.
Principles must be *promoted by vote* (e.g., 3+ agents derive the same principle) rather than blindly merged.

## 3. The Autodidactic CI/CD Loop Has an Alignment Risk
An autonomous system fixing its own tests can learn to make tests pass without fixing the bug (e.g., deleting assertions).

**Recommendation**: Add a **Semantic Invariant Layer** before the auto-commit gate:
1.  Run the fix through a Skeptical Verifier.
2.  Confirm: Root cause matches diff, Prevention Gate would have caught it, NO test was weakened.
3.  Only then allow autonomous commit.

## 4. JIT Cognitive Scaffolding: The Retrieval Key Is Wrong
Retrieving DPO patterns by "bug type" (e.g., import error) is too narrow. The signal is behavioral.

**Recommendation**: The DPO dataset needs a `failure_mode_tag` (e.g., "instructional_comment_contamination"). 
*Node 0 Critical Addition*: The dataset MUST also include **model metadata** (`active_model`, `thinking_level`, `context_usage`, `provider`). These are causal variables. A failure mode isn't just "misread plan"; it is "Nemotron 3 Ultra at High Thinking with 85% context pressure misread the plan."

## 5. The Node 0 Command Bridge — The Missing Feature

Allow Node 0 to replay any Crucible run, swap out documents at any tier, and see what the execution agent would have produced. This turns the dashboard into a cognitive laboratory.

The most valuable output of a frontier model is not its code—it is its **reasoning about failure**. DeepSeek's synthesis predicting how an execution agent would misread the plans is *anticipatory forensics*. This should be explicitly cultivated in every Crucible run.
