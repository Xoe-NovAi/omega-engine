## THE PART THAT IS USABLE — two named anti-patterns

These are the highest-value output, and they are **conceptual claims, not
citations.** They need no source to be useful; they name what we are living.

### 1. "Autogenerated-as-authoritative"
> A **generated** artifact that is committed and then read as if hand-maintained.

Categorically worse than either stale hand-written docs or an obviously-generated
file being ignored, **because it has the appearance of authority.**

Our instances:
- `EXPERT_SESSION_REGISTRY.md` — generated, 5 weeks stale, consulted for a live
  session id, found nothing, and the reader concluded no session existed
- `STATE_OF_THE_REALM.md` — presented as a live cockpit; carried **inverted ACL
  claims** (8017 granted, 8019 not) for three days

### 2. "Authority inversion"
> A **lower-tier** document — a comment, a generated file, a snapshot — is read
> as **more** authoritative than the higher-tier source of truth that supersedes it.

This is the *mechanism* behind the other defects, not a separate class:
- A model ID stamped into a source header, read as live provenance
- A comment satisfying a text-grep gate
- A hand-curated registry overriding a live query

**Both anti-patterns have the same root: nothing in the artifact declares what
kind of claim it is making, or what outranks it.**

## THE RECOMMENDATION (design proposal, not an implementation)

> Add a mandatory header to every doc under `data/coordination/` and `docs/`:
> **`status:` · `owner:` · `supersedes:` / `superseded_by:`**
> …and make generated files **declare themselves generated**.
> Then a small CI check greps docs for referenced paths, branches and symbols and
> fails if they do not resolve.

**Why this is the highest-leverage item in the run:** it is one convention, it is
enforceable, and **it would have caught four of the six documentation defects**
(stale registry, stale cockpit, sprint file naming a non-existent branch, three
unmarked policy files).

The two it would not catch — the M9 comment-wording gate and the ACL inversion —
are code and permission defects, and need different gates.

**Jem's staleness heuristic, worth stealing immediately and cheap:**
> Flag docs whose **referenced identifiers no longer exist in the code** — regex
> the paths, branches and symbols out of docs, cross-check with `rg`. Fail if
> they do not resolve.

That is a ~20-line script, and it is a direct detector for "the sprint file names
a branch and a test that do not exist." **It also has the property that it can be
observed red**, which is the only kind of gate this project has learned to trust.

## FRAMEWORKS NAMED — RESEARCH AGENDA ONLY, **NOT CITATIONS**

Jem is confident these are real; **she did not read them.** Treat as a reading
list for a future dispatch, never as support for a design decision.

- **Architecture Decision Records (Nygard)** — status lifecycle with an explicit
  `Superseded by ADR-XXXX` **link**. The link is the transferable idea: supersession
  as a *graph*, not a hierarchy.
- **Divio taxonomy** — Tutorial / How-to / Reference / Explanation. Not about
  authority, but forces a doc to declare what kind of claim it makes.
- **Kubernetes Enhancement Proposals** — explicit status enum plus named
  owners/reviewers. Closest public analog to a status vocabulary.
- **IETF BCP ("Best Current Practice")** — the *named* concept for "this document
  makes a standing claim," as distinct from an `Internet-Draft`, which is
  point-in-time. **This is the distinction the W40 SOTE banner improvised**, and
  it turns out to have a name.
- **ISO/IEC 82079-1**, **NASA Systems Engineering Handbook Rev 2** — regulatory-tier
  traceable-document practice: revision number, effective date, supersession.
- **Rust API Guidelines / rustdoc** — `cargo test --doc`: a wrong doc example is a
  red build. The mature form of executable documentation.

**The sharpest distinction from that list, applied to us:**
> A **snapshot** is ADR-class — point-in-time, authored by a decision, not
> maintained as current truth.
> A **standing claim** is BCP-class — maintained, has an owner, and is expected
> to be current.
> **Our failure was never the absence of vocabulary. It was that both classes
> lived in the same directory with the same filename pattern, so nothing told a
> reader which contract a given file was under.**
