# Why the 23 Sovereign Mandates?
# ⬡ OMEGA ⬡ JEM ⬡ la-docs ⬡ explanation ⬡ why-22-mandates

The 22 Sovereign Mandates (M1-M22) are the "Constitutional Law" of the Omega Engine. They are not mere suggestions; they are non-negotiable constraints that ensure the engine remains a sovereign tool rather than a corporate dependency.

## The Core Philosophy: Severing the Umbilical Cord

The primary goal of the Omega Engine is to eliminate the dependency on "Big AI" (centralized cloud providers). To achieve this, the mandates focus on three pillars:

### 1. Technical Sovereignty (M1, M6, M7, M8, M16)
- **Local-First (M7)**: If it can run locally, it must. Cloud is a teacher, not a crutch.
- **Zero Telemetry (M8)**: The engine does not phone home. Your data is yours.
- **AnyIO Absolute (M1)**: Ensures the engine is portable and not locked into a specific async runtime.
- **Podman Sovereignty (M6)**: Prevents host-user lockout via the `keep-id` protocol.

### 2. Cognitive Integrity (M5, M9, M11, M17, M21, M22)
- **Gnosis Preservation (M5/M11)**: Intelligence must not be lost between sessions. The L1→L2→L3 distillation pipeline transforms stateless interactions into a stateful soul.
- **Error Integrity (M9)**: Silent failures are the enemy of sovereignty. Every error must be typed and traceable.
- **Response Provenance (M22)**: You must know exactly which model generated a response. "Local" must mean local.

### 3. Architectural Purity (M2, M3, M4, M10, M13, M14)
- **Engine-Stack Firewall (M2)**: Keeps the universal runtime separate from specific content (WADs).
- **Sequentiality (M4)**: Plan → Verify → Execute. Prevents the "Restart Cycle."
- **Temple-Grade (M13)**: Sets a quality bar that exceeds enterprise standards.
- **Heritage Vetting (M14)**: Ensures id Software patterns are used intentionally, not blindly.

## How to Use the Mandates
When designing a new feature or auditing code:
1. **Check the Mandate**: Does this change violate any of the 23 laws?
2. **Document the Tradeoff**: If a mandate must be relaxed (rare), it must be documented in `PIVOT_LOG.md` with a justification.
3. **Verify via CI**: Run `make temple-grade` to ensure compliance.
