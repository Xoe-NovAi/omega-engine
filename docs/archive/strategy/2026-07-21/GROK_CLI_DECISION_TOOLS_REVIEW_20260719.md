## 1. Schema review

### 1.1 What works

- **ADR-shaped records** (`status`, options with risk/consequences, typed relationships, supersession) match Structured MADR / Nygard practice and fit Omega’s YAML-first culture.
- **`extra`-style forbid discipline** (unknown keys fail validation) is consistent with the recent WadManifest V2 lesson: **versioned explicit fields, not `extra=allow`**.
- **Agent-specific fields** that earn their keep in T0:
  - `authority`: `human | agent | human_review`
  - `decision_by` (ISO date) — optional, useful for `list --overdue`
  - `meditate_ready`: bool
  - `relationships[]` with closed enum of types
  - `options[]` with stable `id` + `label`

### 1.2 Over-engineering for T0 (cut or park)

| Proposal | T0 recommendation |
|----------|-------------------|
| Full **MAD `authorization.roles` + speech_acts + stages** (Correction 6) | **Cut from T0.** Encode as conventions + CLI gates (`--human-confirmed`). Revisit at T3. |
| Weighted **`criteria` scores** as first-class required schema | **Optional**, not required. Prefer free-form `drivers` + optional `criteria_scores` map. Scoring is deliberation output, not storage obligation. |
| Per-decision **`persona_parameters` with mythic names** (Sekhmet, Brigid, …) | **M2 hazard.** Use **`slot_ref` keys** (`P1`…`P10`, `GRAND_OVERSIGHT`) or omit until overlay resolution exists. Defaults live in WAD meditate config, not engine. |
| Full Structured MADR **audit / technologies / audience** | Optional tags only. Do not block parse. |
| **DEBATE replay retrospective** fields | T5 only. Empty `retrospective: null` is enough. |

### 1.3 Missing fields (add in T0)

```yaml
  primary: "..."
  secondary: []

# Decision outcome (set only on accept path / superseding record)

decided_by: null           # agent_id or "human"
rationale: null            # short string
supersedes: null
superseded_by: null
evidence_refs: []          # paths / handoff ids / commits — cheap provenance
```

**JSON Schema**: yes for CI/`decide` validation. Keep **one** schema file under e.g. `config/schemas/decision_v1.json` (or `docs/decisions/schema/`) and load via existing config patterns — not a second YAML dialect.

### 1.4 Status machine

Correct **logical** machine:

```
proposed ──► accepted
    │            │
    │            └──► superseded   (only via NEW record that supersedes this id)
    └──► deprecated                (rare; no successor)
```

**Implementation nuance (ADR purity vs git reality):**

- Golden rule: **do not rewrite accepted decision body** (options, drivers, rationale of the past).
- **Allowed mutation on the superseded record**: set `status: superseded`, `superseded_by: D24`, `updated:` only — or keep original immutable and express supersession **only** on the new file + an index.  
  **Recommend for T0**: allow a **minimal status patch** on the old file (status + superseded_by + updated). Reject any other field changes on non-`proposed` records.

Do **not** “move file from `open/` to `decided/`” as the primary mechanism if it breaks stable paths and git blame. Prefer:

```
docs/decisions/catalog/D001.yaml   # stable path for life of id
```

Optional index: `docs/decisions/INDEX.yaml` regenerated by `list` (not hand-edited).

## 2. Architecture review

### 2.1 DecisionEngine abstraction

| Question | Recommendation |
|----------|----------------|
| Class vs module | Thin **`DecisionStore` / `DecisionEngine`** class is fine — mirrors `EntityRegistry` style. Avoid god-object. |
| Location | **`src/omega/governance/decisions.py`** (or `src/omega/decisions/`) inside the monorepo. **Not** a separate PyPI package for T0. |
| Package boundary | CLI in `src/omega/cli/decision_cli.py` + `app.add_typer(..., name="decision")` next to `youtube` / `bundle`. |
| Data plane | **Git-tracked YAML under `docs/decisions/catalog/`** is correct for ADRs (reviewable, pushable). Runtime state does **not** belong in SQLite for T0. |

### 2.2 CRUD + supersession

Sound design if:

1. **`create` / `update`** only while `status == proposed` (full body edits).
2. **`accept` / `decide`**:
   - writes **new** file `D{n+1}` with `supersedes: D{old}`, `status: accepted`, `chosen_option`, …
   - patches old: `status: superseded`, `superseded_by: D{n+1}` (minimal).
3. **Never** overwrite accepted option text.

Naming: prefer **zero-padded ids** (`D001`) for sort stability once count > 9.

### 2.3 Atomic writes & concurrency

- **`write tmp → os.replace`** (or existing `batch_writer` pattern): **required**.
- **Concurrent multi-agent writes**: real risk on HMC. T0 options (pick one, document):
  1. **Convention**: only Kali (or single `decider` agent_id) runs `decide` — enforce in CLI via env/`authority` + optional allowlist.
  2. **Advisory lock file** `docs/decisions/.lock` with TTL (file-based, AnyIO-friendly).
  3. **Defer flock/sqlite** until pain (aligns with “build from pain”).

**Do not** invent Redis locks for decisions.

### 2.4 Cache

- **T0: always read from disk** for `list`/`show`/`decide`. 23–50 YAML files is nothing.
- In-memory graph cache only if profiling says so (T1-graph+). Invalidate on any write.

### 2.5 Engine-stack firewall (M2)

Critical:

- Decision tooling in `src/omega/` must **not** import ANAi entity names or WAD-specific myth.
- MEDITATE scaffold must resolve **slots → lenses via active IWAD**, same as `meditate/lens_registry.py` direction.
- Catalog content (D1 text about Sekhmet) may mention myth; **engine code must not**.

| Fit with monorepo | High | Typer CLI pattern already exists |
| Crash safety | High if atomic | Standard |
| Multi-agent safety | Medium | Needs explicit single-writer policy |
| M2 safety | Medium | Fix persona key design |

## 3. CLI review

### 3.1 Namespace

**`omega decision …` is correct.**

- Matches existing sub-apps (`youtube`, `bundle`).
- `omega adr` is jargon-heavy for agents; `omega decide` collides with verb vs noun group.
- Keep noun group: `decision list|show|decide|graph`.

### 3.2 Commands (T0+T1-core)

| Command | Required T0? | Notes |
|---------|--------------|--------|
| `list` | Yes | Filters: `--status`, `--tag`, `--overdue`, `--meditate-ready` |
| `show ID` | Yes | Print YAML + **supersession chain** (walk `supersedes` / `superseded_by`) |
| `decide ID --option OPT` | Yes | Creates successor; optional `--rationale`; **`--human-confirmed` only when `authority` ∈ {human, human_review}** |
| `graph` | T1-graph | ASCII only; `--focus`, `--depth`; plain text default (agent-safe) |
| `validate` | Nice 30-min add | Run JSON Schema over catalog — high ROI for migration |

### 3.3 Flags & UX

- **`--human-confirmed`**: **not always**. Gate by `authority`. For `agent` authority, log `decided_by=agent_id` from Hivemind/env.
- **Color**: Rich tables OK for humans; **`--plain`** for handoff paste / CI.
- **Exit codes**: non-zero on validation failure, unknown id, missing human confirm — agents need this.
- **Idempotency**: `decide` on already-accepted id should **error** (force explicit supersede of latest head).

### 3.4 CLI score

Design is clean and adr-tools-evolved. Main fix: **authority-aware confirm**, not blanket flag.

## 4. MEDITATE integration review

### 4.1 Are BE uptake/anchoring parameters meaningful in single-inference MEDITATE?

**Partially — with caveats. Risk of cargo-cult is real.**

Belief Engine’s `u` / `a` are **controls on iterative log-odds updates across evidence steps**. A **single** oracle call that role-plays 10 personas does **not** run that loop unless you:

1. structure the prompt into explicit Extract→Judge→Update stages, **and**
2. either multi-call or force the model to emit intermediate belief states.

What **is** still useful in T1-scaffold:

- **Named stance biases** as *prompt annotations* (“P1: high anchoring on hardware constraints”) — qualitative, not numerical magic.
- **Reproducibility**: same decision file → same scaffold text → better audit than free-form chat.
- **Separation**: deliberation config lives with the decision, not in agent memory soup.

What is **not** honest for T1:

- Claiming numerical `uptake: 0.4` is a calibrated BE parameter without multi-step update + measurement.
- Hardcoding ANAi persona tables in core.

### 4.2 Where should parameters live?

| Layer | Owns |
|-------|------|
| WAD meditate lenses / overlay | Default stance hints per **slot** |
| Decision file | Optional **overrides** for this question only |
| Engine | Template renderer only — no mythic defaults |

### 4.3 5-step BE loop inside one oracle call?

**Implementable as prompt structure, not as real BE.** Ship T1-scaffold as:

```
omega decision meditate-scaffold D1   # or: omega meditate --decision D1 --scaffold-only
→ writes / prints prompt markdown
→ human or agent runs inference separately
```

**Do not** auto-call the model inside T0/T1 unless you already have a stable meditate path and budget for flakes.

### 4.4 MEDITATE score

| Item | Recommendation |
|------|----------------|
| T1-scaffold in 7h sprint | **Optional / cut first** if schedule slips |
| Numeric u/a in YAML | **Defer to T2** or store as optional opaque map with no engine math |
| Slot-keyed hints | **Yes** |
| Full automated MEDITATE | **T2**, pain-triggered |

**`decide` algorithm (minimal):**

1. Load + schema-validate target.

6. Write new accepted record (atomic).
