**Owner:** doom_guy (S1) · **Service:** `omega-exchange.service` (systemd **user** unit, `Linger=yes`)
**Origin:** `scripts/omega_exchange_server.py` (AnyIO/starlette/uvicorn, loopback-only)
**Status:** verified 2026-09-29

---

## ⚠️ THE ONLY SUPPORTED URL FORM

```
https://n0.tail51f14a.ts.net:8019/<path>
```

**HTTPS only. Use `curl -f`.**

```bash
# correct — refuses to write a file on failure
curl -sf -o /tmp/artifact.zip https://n0.tail51f14a.ts.net:8019/<path>
```

## ❌ THE BROKEN URL FORM — NAMED EXPLICITLY, DO NOT REDISCOVER IT

```
http://100.123.51.67:8019/<path>     ← BROKEN. DO NOT USE.
```

The tailnet IP speaks **HTTPS**. A plain-HTTP request is rejected by Tailscale's TLS
terminator with:

```
HTTP/1.0 400 Bad Request

Client sent an HTTP request to an HTTPS server.
```

**48 bytes of ASCII.** `curl -o` writes that to disk exactly as it would a
successful download:

```
$ curl -o /tmp/tail.zip http://100.123.51.67:8019/full-pack-20260926.zip
$ file /tmp/tail.zip
/tmp/tail.zip: ASCII text                    48 bytes     ← NOT the artifact
$ sha256sum /tmp/tail.zip
7a1fabf2...                                  ← does not match the manifest
```

A receiver that skips verification writes a 48-byte "zip", believes the transfer
worked, and fails much later at `unzip` — far from the cause. **That is the
false-success bug this origin was rebuilt to close.**

### Why the origin cannot fix that specific 48 bytes

The response is generated by **tailscaled** (Go `net/http`), not by this service.
Proof — the journal shows a TLS handshake failure, and the origin's own access
log records **no** such request:

```
journalctl -u tailscaled | grep "TLS handshake"
  http: TLS handshake error from 100.123.51.67:55616:
        client sent an HTTP request to an HTTPS server
```

The plaintext connection dies **before** the origin is reached. No origin-side
change can suppress that response body. What this service does instead is make a
false success **impossible for a correct client**, in three layers:

1. **`curl -f`** — the documented form. Exit 22, and **no file is written**.
2. **Manifest-first verification** — `/manifest.json` publishes `size` and
   `sha256` for every artifact, so a client can verify *before* accepting bytes.
3. **Self-describing errors** — every error this origin returns is a JSON
   envelope tagged `X-Omega-Error: 1`. No error body is ever a plausible payload.

## Verification procedure (the manifest rule)

```bash
# 1. get the manifest
curl -sf https://n0.tail51f14a.ts.net:8019/manifest.json -o /tmp/m.json

# 2. read the expected size + sha256 for the path you want
python3 -c "import json;d=json.load(open('/tmp/m.json'));\
e=[x for x in d['entries'] if x['path']=='full-pack-20260926.zip'][0];\
print(e['size'],e['sha256'])"

# 3. download with -f
curl -sf -o /tmp/artifact.zip \
  https://n0.tail51f14a.ts.net:8019/full-pack-20260926.zip

# 4. VERIFY — both must match, or the transfer failed
sha256sum /tmp/artifact.zip
stat -c%s /tmp/artifact.zip
```

You can also verify from response headers before hashing the body:

```
X-Omega-SHA256: 36ac1468f2397c00effd4634df75ee7038a4954d2e91c3b5655d1bc200af5a2e
X-Omega-Size: 122463
X-Omega-Error: 0
```

## Endpoint reference

| Endpoint | Method | Purpose |
|---|---|---|
| `/manifest.json` | GET/HEAD | path, size, sha256, content_type, mtime for every artifact |
| `/` | GET/HEAD | index — service id, count, path list, URL forms |
| `/healthz` | GET/HEAD | liveness (same shape as `/`) |
| `/<path>` | GET/HEAD | the artifact, with `X-Omega-SHA256` + `X-Omega-Size` |
| `/<path>` | PUT/POST/DELETE/PATCH | **405** — read-only surface, refused loudly |

## Security posture

- **Loopback-only.** The origin refuses to start on a non-loopback `HOST`; the
  service exits 2 with a FATAL message. The tailnet boundary is Tailscale Serve,
  which applies the packet filter. Binding `0.0.0.0` would put this on the LAN —
  the exact defect class `make check-lan-exposure` exists to catch.
- **Path containment.** Traversal (`../`, encoded variants) resolves inside the
  root or is refused. Symlinks out of the root are never followed.
- **Error envelopes.** `X-Omega-Error: 1` + JSON body. Never a bare body.
- **Verifiable responses.** `Content-Length` and content type are asserted on
  every response; artifacts carry their own sha256 in a header.

## Access log (the falsifiability requirement)

`python3 -m http.server` wrote **no** access log, which is why we could assert
"the log has never shown a hit from N1" about a log that did not exist — a
successful pull and a failed pull were indistinguishable.

The origin now emits one JSON line per request to stdout → systemd journal:

```bash
journalctl --user-unit=omega-exchange.service -f
```

Real captured line (a genuine tailnet request from N1's address):

```json
{"ts":"2026-09-29T08:28:25.867+00:00","service":"omega-exchange/2.0","method":"GET",
 "path":"/full-pack-20260926.zip","status":200,"bytes":122463,
 "client_ip":"100.123.51.67","user_agent":"curl/8.14.1",
 "note":"sha256=36ac1468f2397c00 dur_ms=0.6"}
```

Fields: `ts` (UTC, explicit `+00:00`), `method`, `path`, `status`, `bytes`,
`client_ip`, `user_agent`, `note` (hash prefix + duration, or a rejection reason).

**If you need to know whether an N1 pull succeeded, this log is where you look.**
