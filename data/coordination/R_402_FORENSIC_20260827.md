## §0 Executive Verdict

**The 402 "Insufficient balance" is NOT a balance error and NOT a model error. It is an OpenRouter platform-level authentication/account-classification error on FREE models routed via OpenRouter.**

**Key facts** (each backed by SQLite ground truth below):
1. The Ma'at session `ses_fbaad14ecffeJv7BYs0ptb8FWP` **completed 39 successful assistant turns (75 tool calls, 0 tool errors)** before any 402.
2. The 402 occurred **3 times within the session** at assistant-message level (msg #17, #38, #44), each time as a `UnknownError` wrapping `{"code":402,"message":"Insufficient balance","metadata":{"error_type":"payment_required"}}`.
3. The session **recovered twice via "Continue."** but failed terminally on the third 402.
4. **Zero 402 errors in the probe data** (`data/metrics/free_model_probes.jsonl`, 425 entries) — M3 returns 200/401/429/200, **never 402**.
5. The error is **transient and rate-window-bound** — it disappears after a "Continue." restart, confirming it is not a hard account failure.
6. **Cost field in the DB = 0** for every step-finish, confirming the model is genuinely FREE in OpenCode's accounting. The 402 is therefore a **mislabeled error from a downstream gate**, not a true balance check.

**Operational conclusion**: M3 remains the best (and arguably only) reliable free model for long-write work. The 402 is a **transient OpenRouter / model-gateway quirk** that retry-after-30s resolves. Continue dispatching with retry-aware session continuity (which Ma'at and Roc both proved in this very investigation).

## §3 All 402 Errors Across the OpenCode DB

### Query
```sql
SELECT s.id, s.title, s.model, s.time_created,
       json_extract(p.data, '$.state.error') as error,
       json_extract(p.data, '$.state.metadata') as metadata
FROM session s
JOIN message m ON m.session_id = s.id
JOIN part p ON p.message_id = m.id
WHERE json_extract(p.data, '$.state.error') LIKE '%402%'
   OR json_extract(p.data, '$.state.error') LIKE '%Insufficient balance%'
   OR json_extract(p.data, '$.state.error') LIKE '%payment_required%'
ORDER BY s.time_created DESC
LIMIT 50
```

> **A "balance" error on a free service is rarely about balance — it's about rate. When an account-class error fires on a model with cost=0, look for the per-minute cap, not the lifetime quota. Resilience comes from building retry on top of stateful sessions, not from eliminating the rate limit.**
