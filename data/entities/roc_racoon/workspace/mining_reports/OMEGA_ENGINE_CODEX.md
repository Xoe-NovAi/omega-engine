## §1 Architectural Anatomy: The "How"
The Engine is designed as a universal runtime, decoupled from any specific platform or model.

### 1.1 The Oracle (The Gateway)
The **Oracle** is the central nervous system. It handles:
- **Intent Detection**: Determining what the user actually wants.
- **Summon Parsing**: Routing requests to the correct entity.
- **Iris Speculative Decode**: Using a small, fast model (qwen3-1.7b) to handle simple queries instantly, escalating complex ones to the Council.

### 1.2 The Model Gateway (The Provider Fabric)
A tiered, **Local-First** routing system that ensures sovereignty:
`native-gguf` $\rightarrow$ `lmster` $\rightarrow$ `Ollama` $\rightarrow$ `Google AI Studio` $\rightarrow$ `OpenRouter` $\rightarrow$ `OpenCode` $\rightarrow$ `Copilot` $\rightarrow$ `Mock`.
It ensures that the system only reaches for the cloud when local capabilities are exhausted.

### 1.3 Memory Store (The Akashic Record)
A hybrid memory system that mimics human cognition:
- **Hot/Warm/Cold/Temp Tiers**: Optimizing for latency and resource usage.
- **Hybrid Search**: Merging FTS5 (keyword) and Vector (semantic) search for high-precision retrieval.
- **Somatic State**: Serialization of model state for instant resumption.

### 1.4 The WAD Architecture (Modular Capabilities)
Inspired by id Software, Omega uses a **Lump-based** architecture:
- **Engine**: The universal runtime.
- **IWADs**: The base implementation (e.g., Arcana-Nova).
- **PWADs**: Modular capability packages (Lumps) that can be added or swapped without touching the core.

### 1.5 The Hivemind (Cross-Agent Coordination)
A sovereign communication layer implemented via the **Omega Hub MCP**:
- **Workspace Locks**: Preventing agent collisions.
- **Live Feeds**: Real-time progress tracking.
- **Context Posting**: Sharing insights across the fleet without redundant inference.
