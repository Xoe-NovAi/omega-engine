### WS-04: ForensicReceipt Pattern Study
**Core**: Ed25519-signed receipt covering `{metadata, payload_hash, timestamp}`
**Properties**: 
- Tamper-evident output hash
- Sealed transformation accounting (prose_tax_summary)
- Identity provenance (node public key)
- Independent verification with public key only
- Key rotation with auditable succession receipts

**Omega M22 Gap**: Current M22 logs `provider_name` from response — observational only. ForensicReceipt makes provenance **cryptographic**.

**Integration Path**: 
1. Add `sovereign-core` as optional dependency
2. Wrap `GenerateResult` with receipt minting
3. Store receipts in `sovereign-ledger` (SQLite + hash chain)
4. Verification CLI: `sovereign-verify --receipt --public-key`

### WS-05: Airlock Pattern Study (SAR-0004)
**Missing in Omega**: Outbound governance boundary. We have inbound (ModelGateway) but no outbound inspection.
**Airlock Components**:
- `NormalizedPayload` — provider-neutral inspection surface
- `PolicyEngine` — YAML rules (raw/fields/telemetry scopes)
- `AirlockBoundary` — async 4-component orchestrator
- `ReceiptBuilder` — evidence assembly + ledger commit
- Transport-agnostic (OpenAI, Anthropic, raw, etc.)

**Omega Need**: Prevent data exfiltration, enforce token budgets, audit outbound tool calls, comply with M8 (Zero Telemetry) by proving nothing leaves.
