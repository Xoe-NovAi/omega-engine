## §3 Soul Distiller Deep Dive

### 3.1 Current State: Three Failures

```
_record_interaction()                    ← Called on every talk()/summon()
  └── _interaction_counter[entity] >= 5  ← Throttle fires
       └── anyio.create_task(close_session())  ← Fire-and-forget
            └── get_history(entity, session_id)
                 └── Returns exchanges with keys: "user"/"assistant"
            └── close_session() builds transcript:
                 role = ex.get("role", "unknown")      ← WRONG KEY → "unknown"
                 content = ex.get("content", "")        ← WRONG KEY → ""
                 → transcript = "[unknown]: \n[unknown]: \n"
            └── distill_and_save(transcript)
                 ├── _extract_narrative()  → Nothing found → boilerplate
                 ├── _distill_insight()    → "Session completed"
                 └── _extract_principle()  → "Every session produces knowledge"
                     → proposed_lessons.yaml gets garbage
```

**Failure 1 — Wrong keys (oracle.py:786-789)**: The exchange format contract is broken. `add_exchange()` writes `"user"`/`"assistant"`, `close_session()` reads `"role"`/`"content"`.

**Failure 2 — Regex-only (entire distiller)**: No LLM calls. The `_extract_narrative()`, `_distill_insight()`, and `_extract_principle()` methods are pure keyword matching. They cannot produce genuine L2/L3 abstractions.

**Failure 3 — No session lifecycle hook**: `close_session()` fires every 5 interactions, not at session end. This means:
- Active sessions get partial distillations (5-interaction snapshots, not full transcripts)
- Session boundaries are meaningless — you get 5-interaction chunks that cross session boundaries
- The distiller runs on the hot path (fire-and-forget, but still consumes I/O)

### 3.2 The Right Fix

#### Immediate (3 min): Fix the Key Mismatch

```python
# In oracle.py lines 786-789, change FROM:
role = ex.get("role", "unknown")
content = ex.get("content", "")

# TO:
role = "user" if "user" in ex else "assistant"
content = ex.get("user", ex.get("assistant", ""))
```

But this is insufficient — it only fixes the mechanical transcription. The deeper issue remains.

#### Short-term (2-3 days): Add LLM-Based Distillation

The distiller needs an optional LLM path. The architecture should be:

```python
class SoulDistiller:
    def __init__(self, model_gateway: Optional[ModelGateway] = None):
        self._model_gateway = model_gateway  # None = regex-only fallback
    
    async def distill_session(self, transcript: str, entity_name: str) -> Dict:
        if self._model_gateway:
            return await self._llm_distill(transcript, entity_name)
        return self._regex_distill(transcript, entity_name)  # existing pattern matching
```

The LLM path should:
- Use a small model (Qwen3-1.7B or similar) — this is NOT a frontier task
- Use structured prompting: "Extract L1 narrative, L2 insights, L3 principles from this session transcript"
- Temperature=0.0 for deterministic output
- Budget: ~200 tokens per distillation call
- Run in `anyio.to_thread.run_sync()` to not block the hot path

**Token efficiency concern (M18)**: A 200-token inference per 5 interactions is ~40 tokens per interaction. Acceptable. But the current regex approach wastes 0 tokens for 0 value. An LLM path would actually produce value.

### 3.3 Lifecycle Considerations

**Should it fire on every talk()/summon() or only on session close?**

The current approach (every 5 interactions) is the **wrong lifecycle boundary**. Here's why:

- **Per-interaction**: Too expensive. Every `talk()` would trigger I/O.
- **Every 5 interactions (current)**: Arbitrary. Session is an arbitrary concept when the distiller slices across boundaries.
- **Session close only**: Better, but sessions in the current architecture are loosely defined (session_id is auto-generated, no explicit close signal).
- **Periodic (every N minutes)**: Best for passive distillation. A background coroutine that sweeps active sessions and distills any with new activity since last check.

**My recommendation**: 
1. Keep the 5-interaction throttle but FIX the key mismatch
2. Add a passive background coroutine that distills sessions with activity >30 min ago
3. Remove `close_session()` from `_record_interaction()` — it fires too frequently and on the wrong boundary

### 3.4 AnyIO Compliance Check

- **Synchronous file I/O**: The distiller uses `open()` + `fcntl.flock()` directly. This is acceptable for bootstrap/setup but should be wrapped in `anyio.to_thread.run_sync()` for the hot path.
- **M1**: ⚠️ PARTIAL — the distiller uses synchronous I/O on what could become the hot path. Currently acceptable because the throttle limits frequency, but should be migrated.

### 3.5 M9 (Error Integrity) Check

- **Bare `except:`**: ✅ PASS (zero occurrences in soul_distiller.py)
- **Error handling**: The distiller has proper logging and error propagation. No silent exception swallowing.

### 3.6 M16 (Modularization) Check

### 4.2 TTL Policy Recommendation

```
Age        → Action
< 14 days  → Keep (within sprint cycle)
14-30 days → Archive (compress, preserve for forensics)
> 30 days  → Delete (past sprint cycle, low forensic value)
```

**Rationale**:
- Sprint cycles are 2 weeks. A stale packet within 14 days might still be picked up.
- 14-30 days provides forensic availability for post-sprint analysis.
- 30 days is the standard data retention minimum for most systems.

### 4.3 Reaper Placement

**Do NOT create a new systemd timer.** The Hivemind already has a pruning loop (20-min heartbeat TTL). Add the handoff reaper as a coroutine in the same loop:

```python
async def _pruning_loop(self):

        await anyio.sleep(PRUNE_INTERVAL)  # 20 min
```

**Effort**: ~2 hours to add coroutine + TTL config + test.
**Risk**: Low — the pruning loop already runs, we're adding one more coroutine.

### 4.4 Dual Handoff System (Cross-Cutting Concern)

The blueprint notes "Dual Handoff Systems: Orchestrator uses in-memory HandoffState while MCP agents use file-based data/handoff/ — cannot exchange."
