## Core Philosophy Pillars

### 1. "Worse is Better" (Richard Gabriel / New Jersey Style)
- Simplicity of implementation > Simplicity of interface
- Ship the 50% solution that works
- Let it spread virally, iterate to 90%
- This is the fundamental strategy: Doom shipped and conquered, then Quake raised the bar

### 2. Carmack's Law
- When assumptions change, rewrite from scratch
- "Sometimes the fastest way to solve a problem is to not have it in the first place"
- Doom→Quake→Q2→Q3→Doom3—each a complete rewrite, not incremental patches
- Incremental patching produces bulkier, markedly inferior code

### 3. Focus Philosophy
- "Focus is a matter of deciding what things you're not going to do"
- Carmack spent 3 months optimizing the pentium for Quake
- One thing at a time, deeply

### 4. Tools-First
- DoomEd before Doom
- The editor shapes the product more than the engine
- "It's the data" — Romero's third principle

### 5. The .plan Culture
- Daily technical updates, published publicly
- Design decisions, dead ends, rationale — all transparent
- Archive spans 10+ years, still studied today

### 6. Modding as Architecture
- WAD format designed for modding before game shipped
- PWAD overlay = zero-risk modding
- Documented format = anyone can build tools
- This sustained Doom for 30+ years

### 7. Open Source Strategy
- Release 1-2 generations behind current tech
- Community maintains and creates new content
- Pattern: Doom→Quake→Q2→Q3→Doom3 → all GPL
